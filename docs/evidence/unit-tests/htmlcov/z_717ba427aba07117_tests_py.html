357class UATGuestDenialTests(TestCase): 

358 """GAP 3: unauthenticated GUESTS must not write UAT evidence. 

359 

360 UATEndpointRBACTests above already covers shopper (allowed) and seller 

361 (403). This class closes the missing third role: the anonymous guest. 

362 

363 WHY THE PAYLOADS ARE FULLY VALID: every body below is one a registered 

364 shopper would get 201 for (same product_id / question_key / phase / value 

365 as the shopper test above). So a refusal here is provably about IDENTITY, 

366 not about a malformed request that would have 400'd anyway. 

367 

368 WHAT IS ASSERTED: 

369 * 401/403 — both write views use permission_classes=[IsAuthenticated], 

370 so DRF refuses the guest BEFORE post() runs. With JWTAuthentication 

371 first in the auth stack the actual code is 401; 403 is accepted too 

372 so the test pins the security property, not one settings detail. 

373 * zero rows in BOTH uat_session and uat_response (and no stray Rating). 

374 * zero cache writes — the UAT views never touch the cache today; this 

375 is a regression guard against a future "just cache it for guests" 

376 shortcut, which FR-1.9 forbids. 

377 * no django_session row — the guest stays ephemeral, exactly as the 

378 guest rating test above asserts. 

379 

380 Nothing here relaxes a permission: views.py, models.py, serializers.py 

381 and accounts/permissions.py are unchanged. 

382 """
